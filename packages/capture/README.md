# Shared guided capture

Student enrolment uses `GuidedCamera(enrollmentGuidance: true)` for a front-first server-issued pose sequence with audio disabled. Local observations advance the pose circles; the recording lasts 10–25 seconds. A missed circle is advisory: playback offers retake or upload for teacher review. Once an upload has started, retry that upload or cancel the attempt before making a replacement recording. The Android app injects an ML Kit frame analyzer; Student web uses `pose_capture.js` with one browser media stream for preview, local MediaPipe analysis and WebM recording. The shared Teacher classroom recorder uses the original 15-second path without pose analysis. This package also provides `PendingClips` for private recoverable native recordings, platform playback, and `ResumableUpload` for signed TUS transfer. It does not grant identities, activate templates or determine attendance.

Student web currently downloads pinned MediaPipe Tasks Vision 0.10.35 runtime assets from jsDelivr and the face-landmarker task model from Google's public model host when guidance starts. These downloads do not upload preview frames, but they require network access and are an external code dependency; bundle and integrity-pin those assets before institute deployment. If guidance cannot load, recording continues with timed prompts and an explicit review warning. The final video still goes through private upload, server quality checks and teacher review.

Native recordings are copied into app-private storage and deleted on completion/cancellation/logout/expiry; web blobs are temporary and do not survive page closure. TUS sends only the publishable API key and object-scoped upload signature to the verified direct Storage endpoint. Resume URLs are checked against that origin/path; no user JWT or server Storage secret enters this transport. Progress/checkpoints support interruption recovery without overwriting an existing object.

Run `../../scripts/flutter test` from this package for the three synthetic transport tests. `tool/probe_upload.dart` is an explicitly opt-in live synthetic transport diagnostic; it requires `FACETRACK_PROBE_FILE` pointing to an ignored private JSON file with a disposable grant/key. Run with `flutter test tool/probe_upload.dart`, then delete the disposable object and grant. It is not part of routine tests and never submits synthetic video to the face worker.
